* Sampler / Preference Model
** The seed problem
   Observation: with fixed params (symmetry, palette, stitch, etc.), changing
   only the seed can take a quilt from hated to loved. The seed controls which
   block patterns land in which cells, diagonal directions, color shuffling, etc.
   But the seed is just a hash input — the param model literally cannot learn
   anything from it. This means the param model has a hard ceiling: it can find
   good parameter neighborhoods but can't distinguish good vs bad quilts within
   that neighborhood.
** Shift weight from params to CLIP
   Once the param model has converged on "bargello + lavender fields + grid
   stitch," the remaining param scores are essentially noise — all candidates
   in that neighborhood score similarly. At that point, CLIP should dominate
   the final selection.
   Proposal: use the param model only as a coarse filter (accept/reject), then
   let CLIP rank among all accepted candidates. Could implement as a threshold
   on param score rather than top-N ranking.
** Cheap visual pre-filters (before CLIP)
   CLIP embedding is expensive (requires forward pass through ViT-B/32). Before
   running CLIP, compute quick image statistics to reject obviously bad quilts:
   - Color entropy: reject quilts dominated by one color
   - Contrast ratio: reject low-contrast quilts
   - Spatial balance: reject quilts where all pattern interest is in one corner
   - Edge density: proxy for visual complexity
   These are pure numpy/PIL operations on the rendered image — much cheaper than
   CLIP. Could cut the CLIP candidate pool in half while keeping quality.
** Track visual feature importances
   After each round, extract simple image stats (entropy, contrast, balance)
   from liked vs disliked quilts. This would reveal whether "good seeds" share
   measurable visual properties — and whether those properties are learnable
   without CLIP.

* Test Quality — Future Work
** Add "params differ → output differs" tests
   Most test_quilt.py feature tests only check PNG header bytes.
   Add tests that render with two different values of a parameter and
   assert the bytes differ. E.g.:
   - wonky=0 vs wonky=0.05
   - sash_width=0 vs sash_width=5
   - border_style=None vs border_style="solid"
   - quilt_stitch=None vs quilt_stitch="grid"
   - wash_alpha=0 vs wash_alpha=0.3
   This catches silent regressions where a parameter is accepted but ignored.
** Strengthen generator route tests
   Several tests only check status 200 without verifying behavior:
   - test_create_with_invalid_preset: verify default params used
   - test_invalid_int_falls_back: verify default rows value in rendered output
   - test_stitch_none_string: verify stitch=None in render kwargs
** Edge case tests
   - rows=1, cols=1 (minimum grid)
   - tile_size=1 (smallest tile)
   - n_colors boundary values (accent_count=0, accent_count=n_colors)
** Reduce probabilistic test fragility
   test_layout.py test_all_macro_templates_reachable sweeps 100 seeds
   hoping to hit all 4 emergent macros. Could hardcode known-good seeds
   for each macro instead.
** Expand doctest coverage
   test.sh only runs doctests for quilt_id.py and clip_embed.py.
   Could add doctests to blocks.py, layout.py, quilt.py.
